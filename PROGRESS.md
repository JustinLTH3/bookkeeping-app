| Transaction date → DATE type  | `Transaction.date` changed from `TIMESTAMP(3)` to `DATE` (`@db.Date`, migration `20260810151502_transaction_date_to_date_type`). Stored timestamps were UTC-shifted by the adapter (app local midnight stored as `23:00:00` of the previous UTC day), so the migration converts existing rows with `USING ((date AT TIME ZONE 'UTC' AT TIME ZONE 'Europe/London')::date)` (app-host tz; dev data corrected +1 day). Storage/compare dates are normalized to UTC midnight (`new Date("YYYY-MM-DD"T00:00:00.000Z)`) in `createTransaction`/`updateTransaction` and via `toUtcMidnight()` for dashboard boundaries; the cash-flow day-bucketing `AT TIME ZONE` conversion became unnecessary and was removed (`GROUP BY date` on the DATE column). Integration helper `createTransaction` and scale-test batches normalize dates the same way. |

| React Hook Form                 | Category and Transaction modal forms converted from controlled `useState` + manual validation to `react-hook-form` (v7) with `zodResolver` (`@hookform/resolvers` v5, zod v4). Sign-in (Server Action) and dashboard time-range select left unchanged (not client forms). |
| Shared zod schemas              | Single source of truth for validation in `src/lib/schemas.ts` (`CategorySchema`, `TransactionSchema`), used by both the server actions (`safeParse`) and the client forms (`zodResolver`). Removes the previous duplicated client form schemas. Schema cannot live in the `"use server"` action files (those may only export async functions), so it lives in a plain lib module. `TransactionSchema.amount` uses a `z.preprocess` that coerces string (client) or number (server) → number and maps NaN/0/empty → 0 so the refine reports "Amount must be a non-zero number" consistently. Because preprocess makes the schema input `unknown`, the client resolver is cast `as unknown as Resolver<TransactionFormValues>` (runtime output is genuinely a number); the client no longer calls `Number()` on submit. Server action contracts unchanged (amount still a number). |
| Type defs in server actions     | Moved the `Category` and `Transaction` data types into their server action files (`src/actions/categories.ts`, `src/actions/transactions.ts`), where `Transaction` replaces the duplicate `TransactionResponse` name. Pages and `CategoryTable`/`TransactionTable` now import these types from `@/actions/*` (type-only imports — no client/server boundary issue) instead of from the page files. Client form value types (`CategoryFormValues`, `TransactionFormValues`) remain local to their pages. |
| `usePaginatedCache` hook        | `src/hooks/usePaginatedCache.ts` — generic client hook extracting the duplicated server-side pagination logic previously inline in both the transactions and categories pages: owns `cache` (`Record<page, items>`), `totalCount`, `currentPage`, exposes `data`, `totalPages`, `goToPage(page, { forceRefresh? })` (clamped; fetches a `±cacheWindow` batched window in one `fetcher(offset, limit)` call only when the page is uncached, or always when `forceRefresh` is set; navigates only after the fetch commits) and `refresh(page?)` (always refetches the window around `page ?? currentPage` — used after create/update). Behavior preserved from the prior implementation (batch window fetch + replace cache); the delete-last-item-on-page path is a single `goToPage(targetPage, { forceRefresh: true })` call. `fetcher` is normalized to `(offset, limit) => { data, totalCount }` (server actions return `{ transactions\|categories, totalCount }`); latest fetcher held in a ref to keep `loadWindow` stable; a request-sequence ref discards stale responses on rapid page clicks — the seq guard also prevents navigating to a page whose window a newer request replaced (a stale `goToPage` no longer moves `currentPage`). `src/app/(app)/transactions/page.tsx` and `src/app/(app)/categories/page.tsx` now use the hook, removing ~40 duplicated lines each. |
| Page loading states             | `usePaginatedCache` now exposes a `loading` flag (initially `true`; set by `goToPage`/`refresh` before a fetch, cleared in `loadWindow`'s `finally` only for the latest request — seq-guarded so stale responses don't flicker and rejected fetches don't leave the page stuck). Categories and transactions pages render a `"Loading categories…"`/`"Loading transactions…"` indicator matching the dashboard's pattern (`px-8 py-10` wrapper + `text-sm text-tertiary`) while loading. |
